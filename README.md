## What This Does

The service accepts writing, scores two signals locally, records its decision, and accepts appeals.

1. A client sends text and a creator ID to `POST /submit`; the route validates the JSON.
2. `detector.model_signal` uses a local language model to score how predictable the text is.
3. `stylometry.style_signal` measures the shape of the text and produces a second score.
4. `scoring.combine_signals` combines the two signals into an AI-likelihood score between 0 and 1.
5. `scoring.score_to_label` maps that score to a guess and a plain-English label, including an unsure band.
6. The service assigns a content ID and records the decision, both signals, score, label, and `decided` status in the audit log.
7. The service returns the content ID, scores, guess, and label to the client, which can show the label to readers. A writer can appeal using the content ID; the appeal is recorded and the item moves to `under_review`.

### False-positive trace

For example, a person writes a simple, predictable paragraph and submits it. Suppose the combined AI-likelihood score is **0.91**: under the ranges below, the guess is `ai` and the reader sees “This writing may have been generated by AI. This is an estimate and can be appealed.” The score is an illustration, not a measured result or a calibrated probability. The writer sends the content ID and their reasoning to `/appeal`; the service records it and changes the current status to `under_review` for a person to examine. The original decision remains in the audit log. A high AI threshold and broad unsure band are intended to reduce accusations, at the cost of leaving more AI writing unflagged; they do not guarantee a low false-positive rate.

### Endpoint contract

Both endpoints accept `Content-Type: application/json` with a JSON object and return JSON.

**`POST /submit` request**

| Field | Type | Meaning |
|---|---|---|
| `text` | string | Required writing; non-whitespace, at most 10,000 characters, and at least three model tokens. |
| `creator_id` | string | Required non-whitespace writer identifier, at most 200 characters. |

**`POST /submit` success: HTTP 200**

| Field | Type | Meaning |
|---|---|---|
| `content_id` | string | Unique identifier for the decision, used to appeal. |
| `guess` | string | `human`, `unsure`, or `ai` according to the score ranges below. |
| `confidence` | number | Combined AI-likelihood score from 0 to 1; higher means more AI-like, including when the guess is `human`. It is not a validated probability. |
| `label` | string | Exact reader-facing sentence for the guess. |
| `model_score` | number | Model signal from 0 to 1, higher meaning more AI-like. |
| `style_score` | number | Style signal from 0 to 1, higher meaning more AI-like. |

**`POST /appeal` request**

| Field | Type | Meaning |
|---|---|---|
| `content_id` | string | Required non-whitespace ID of an existing submission, at most 200 characters. |
| `reasoning` | string | Required non-whitespace explanation, at most 10,000 characters. |

**`POST /appeal` success: HTTP 200** returns `content_id` (string), `status` (`under_review`), and `message` (`"Your appeal has been recorded for review."`). Each valid appeal is appended to the log, including repeated appeals; no automatic recheck occurs. The latest appeal establishes the current status while earlier log entries remain intact.

For either endpoint, invalid JSON, a non-object body, missing fields, wrong types, blank values, or values outside these limits return HTTP 400 with `{"error": "invalid_input", "message": "..."}`; the message identifies the problem. An unknown appeal ID returns HTTP 404 with `{"error": "not_found", "message": "Content ID not found."}`. If the detector cannot load, `/submit` returns HTTP 503 with `{"error": "detector_unavailable", "message": "Detector is unavailable."}`. Unexpected failures return HTTP 500 with `{"error": "internal_error", "message": "The request could not be completed."}`. A successful response is sent only after its audit entry is recorded.

## Signals and Scoring

<!-- For each signal: what property it measures, why that might differ between
     human and AI writing, and WHAT IT CAN'T SEE.

     The blind spot is not optional. If you can't name it you don't understand
     the signal yet — and unit 8's attack set is built out of blind spots. -->

### Signal one — the model signal

**What it measures:** `detector.py::model_signal` uses a local language model's perplexity: how predictable the text's tokens are in context. It examines at most the first 400 tokens.

**Why that might differ between human and AI writing:** Generated text may use choices a language model finds likely, while a person's unusual wording can be less predictable. This is a tendency, not proof of authorship.

**What it can't see:** It cannot know who wrote the text or see the writing process. Plain human writing, including writing by a second-language learner, can be predictable; unusual or edited AI text can be less predictable. It also cannot assess text beyond the token limit.

### Signal two — the style signal

**What it measures:** `stylometry.py::style_signal` uses sentence-length spread, word variety, and punctuation density to describe the text's surface patterns.

**Why that might differ between human and AI writing:** Different writing processes can produce different repetition, sentence rhythms, and punctuation habits, although these patterns overlap greatly.

**What it can't see:** Surface counts cannot understand meaning, intent, or authorship. Word tokenization currently recognizes only ASCII letters, digits, and apostrophes, so other scripts are poorly represented. Genre, text length, quotations, typos, and editing can change the measurements for either a person or an AI.

### The combining rule

<!-- Write the rule in words, then give the numbers. What happens when the two
     signals disagree? -->

**The rule:** Take a weighted average of the two AI-likelihood signals. When they disagree, the average falls between them; a high style score alone cannot determine an AI label.

**The numbers:** Model 0.80; style 0.20. These are initial design choices, not weights learned or validated against an authorship dataset. The broad unsure band reduces confident labels, including false accusations.

**Where it lives:** `scoring.py::combine_signals`

<!-- ⚠️ The grader checks your code against that line. If your rule lives
     somewhere else, say where. -->

**A case where my two signals split, and what my rule does with it:** An excerpt from the human-written Declaration of Independence scored 0.9944 on the model and 0.4699 on style. The weighted result was 0.8895, which fell in the original 0.85 AI band: a real false positive on this example. Model weighting overwhelms the disagreement; the broad band does not prevent every accusation.

Calibration on four short examples (scores from one run, not an accuracy study):

| Text | Model | Style | Combined |
|---|---:|---:|---:|
| Assistant-generated general paragraph | 0.7003 | 0.6078 | 0.6818 |
| Human: adapted opening of *Moby-Dick* | 0.3169 | 0.2902 | 0.3116 |
| Human: Declaration of Independence excerpt | 0.9944 | 0.4699 | 0.8895 |
| Lightly edited assistant-generated paragraph | 0.5576 | 0.5264 | 0.5514 |

The style signal uses population standard deviation divided by mean sentence length, unique words divided by all words, and punctuation characters divided by all characters. It combines 40% of `1 - min(spread / 0.8, 1)`, 30% of `1 - word variety`, and 30% of `1 - min(punctuation density / 0.12, 1)`. For fewer than two sentences the spread component is neutral (0.5). Lower variation, variety, or density increases this heuristic score; none establishes authorship.

## Label Variants

<!-- The exact text of all three labels, as a reader would see them, and the
     score range each covers.

     Write them for someone who has never heard the word "threshold". -->

| Label | Score range | The exact text a reader sees |
|---|---|---|
| high-confidence human | 0.00–0.15 inclusive | This writing appears more likely to have been written by a person, but the estimate may be wrong. |
| unsure | greater than 0.15 and less than 0.8896 | We can't tell reliably how this writing was created. You can appeal this assessment. |
| high-confidence AI | 0.8896–1.00 inclusive | This writing may have been generated by AI. This is an estimate and can be appealed. |

These are the current Part 2 ranges. The original Part 1 AI cutoff was 0.85; its recorded sample responses below remain historical evidence. Neither a label nor a score proves authorship or has been calibrated as a probability.

**Why I worded the "unsure" one this way:** It states the uncertainty without accusing the writer and tells them that an appeal is available.

At the original 0.85 AI cutoff, all three labels were returned by live submissions. The human-band input was an artificial rare-word sentence, the unsure input was an assistant-generated paragraph, and the AI-band input was a human-written Declaration of Independence excerpt. This establishes reachability for those inputs, not reliable authorship detection. Part 2 below records the later three-trial experiment and its corpus limitations.

## Rate Limiting

**Limits:** 10 submissions per minute and 200 per day on `/submit`.

Ten per minute permits ordinary revisions while constraining rapid threshold probing; 200 per day limits sustained use by one claimed identity. These are operational choices, not measured production capacity.

**Declared stretch feature:** Per-creator limits use the existing starter key function. A non-blank string `creator_id` is the key; otherwise requests count against their address. This separates writers at a shared address, but an unauthenticated creator ID can be rotated. In-memory counts reset on restart and are not shared across workers.

**Recorded flood:** The model was warmed before the burst. `run_attacks.py::run_flood` returned:

```text
200 200 200 200 200 200 200 200 200 200 429 429 429 429 429
```

Five 429 rejections were logged. Unit tests also verified the daily cap while advancing through minute windows, creator separation, and address fallback.

Decisions contain all nine required fields. Validation refusals, short-text failures, model unavailability, and limiter refusals leave rejection entries; rejections have fewer fields because no decision exists. Appeals append `under_review` events without overwriting decisions.

Each phase used a fresh service process with limiting enabled. No counter reset occurred inside either attack run. Evaluation requests used a unique creator per phase, criterion, trial, and sample, preventing unrelated rate limits from replacing the intended tests.

### Diagnoses and verdict reasoning

- Criteria 1 and 2: the route and scores were exercised, but the personal-authorship prerequisite was not established. All three fixture trials had 0/10 reference AI flags and a score gap of 0.23268 (reference mean 0.39535, comparison mean 0.62803). These measurements do not resolve the original authorship claims.
- Criterion 3: MET before because all three guesses and exact label/range matches occurred in all trials. MISSED after: only human and unsure remained in the frozen set, although every returned label still matched its range. The stage is label mapping; moving the cutoff above L02 at 0.8895 removes the only AI result from that set.
- Criterion 4: MET in both phases. Every trial recorded all five appeals with the exact reason, retained the original decision, and placed the matching item under review.
- Criterion 5: MET in both phases. Every trial returned five HTTP 400 invalid_input responses, wrote rejection events, and created no decision for those requests.

## The Improvement

**One behavior change:** Raise only `AI_THRESHOLD` from 0.85 to 0.8896. The model, style signal, weights (0.8/0.2), human cutoff (0.15), validation, label sentences, and limiter are unchanged.

**Selection:** The human-written historical reference L02 scored 0.8895, higher than all eight staff false-positive examples. The new cutoff is one four-decimal increment above that confirmed-human calibration maximum. Because the reference fixtures do not verify personal authorship, they were excluded from this calibration pool. The diagnosis and exact value were committed before the after runs; see [baseline diagnosis](results/baseline_diagnosis.md). This tunes observed examples and provides no unseen-data accuracy estimate.

## What's Still Broken

- EV01-EV09 still avoid the AI label. Next, measure the effect of the specific typo, sentence, punctuation, and opening edits against matched controls before considering another signal or weight change. Those were deferred to keep this one-change experiment interpretable.
- MF03-MF06 still receive authorship decisions on control characters, punctuation-only text, a repeated single word, or emoji. Next, add a supported-writing/input-quality gate and test legitimate edge cases; validation was deliberately not changed alongside the threshold.
- Criterion 3 now misses on the frozen set. Keep that honest result; assess a new, separately versioned coverage set to distinguish sample coverage from global label reachability. Do not replace the original examples to repair this verdict.
- The original personal-writing conditions in criteria 1 and 2 remain unverified. A new experiment with documented personal pieces is needed to evaluate those authorship claims; the present fixture results exercise scoring behavior only.
- Per-creator limits can be bypassed by changing IDs, and the counters reset with the process. Authentication and shared persistent limiter storage would be needed for real deployment. Both are outside this local experiment.
- MF07 now receives unsure, but the system still lacks validated multilingual authorship support. A threshold change does not fix either signal's language limitations.

**The production trade:** I would favor fewer accusations against real writers, accepting that more AI text would receive unsure and require moderation. The site and its reviewers would bear that extra work rather than make writers bear unsupported accusations.
